# M5 historical copied-state controller

The protected `m5-historical-copied-state.yml` workflow is pinned to the Mini transition from signed source `3da50fe3a3c9f37d64e24c03a7dcfea94153da58` to signed target `3602e7e3d5fe5c0ef333b4041580d48ec15b24c5`. It runs only from protected `master`, in `m5-mini-release-rehearsal`, on a dedicated macOS ARM64 runner labeled `norn-m5-isolated`. The runner must carry owner-only copies of the historical backup, proof, completed shadow receipt, both signed releases, and the pinned release public key. The protected environment variables name those paths. No backup bytes or credentials are uploaded to GitHub.

Before enabling the runner, install the reviewed `v2/scripts/mini-m5-isolation-check` as a root-owned, runner-immutable executable at `/Library/PrivilegedHelperTools/norn-mini-m5-isolation-check`. Grant the runner passwordless `sudo` only for that exact checker and `norn-m5-isolated-01` argument. Its SHA-256 and root-owned parent path are pinned in the controller; an arbitrary root-owned executable cannot stand in. It verifies the dedicated runner identity, macOS ARM64, enabled `pf`, the attached `com.norn.m5.historical` anchor's outbound deny rules for private IPv4, Tailscale and ULA IPv6 ranges, and absence of private overlay routes. The controller separately rejects credential-bearing environment variables and compares the checker's machine-readable firewall and route attestation before and after restore. The runner's DNS and GitHub transport must use public endpoints compatible with those deny rules. The workflow fails if any host gate is absent.

The controller pins the SHA-256 of the retained proof (`6d24389b…`), dump (`10d29a77…`), completed shadow receipt (`ec18f14d…`), and release public key (`05144c75…`) as independently read from the Mini on 2026-11-02. It checks those exact bytes, safe ownership/mode and both signed releases before creating a new private restore and signed shadow LaunchAgent receipt. The private-copy helper admits the historical pair only with `NORN_M5_HISTORICAL_ISOLATED=1`, the exact old shadow receipt and target SHA, and no `NORN_DATABASE_URL` or audit key. Its normal fresh transition path still uses the one-hour protected-backup verifier. The historical helper only restores to a socket-only disposable PostgreSQL server, runs candidate migrations and passive checks, and compares original table fingerprints. It does not switch the live Mini release or replay the consumed transition journal.

This workflow proves a new isolated restore and signed target shadow run once its receipt is reviewed. It does not close M5 by itself. A separate protected controller step must still exercise the durable upgrade and admitted rollback or signed forward-recovery boundary against the disposable copy, compare source and target workload IDs/routes/periodic schedules, and measure application requests separately from API interruption. Retain both the new receipt and the runner isolation attestation until that step is complete.
